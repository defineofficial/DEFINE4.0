NOTEVAULT - PROJECT DOCUMENTATION
================================================================================

PROJECT OVERVIEW
--------------------------------------------------------------------------------
NoteVault is a centralized, premium learning-resource management platform designed 
for engineering students. It aims to solve the problem of scattered study materials 
by providing a single hub to discover, organize, and access notes, PDFs, videos, 
and GitHub repositories.

CURRENT TECH STACK
--------------------------------------------------------------------------------
- Frontend Framework: React 18
- Build Tool: Vite v5
- Routing: react-router-dom v6
- Styling: Vanilla CSS with custom CSS variables (Premium Dark Mode, Glassmorphism)
- Icons: lucide-react
- Backend / Database: Supabase (PostgreSQL, Authentication)

CORE FEATURES & CAPABILITIES
--------------------------------------------------------------------------------
1. Authentication System
   - Live integration with Supabase Auth.
   - Users can Sign Up and Sign In securely.
   - Unauthenticated users can browse, but cannot save or add resources.

2. Resource Library
   - A global feed displaying all materials uploaded by the community.
   - Displays custom Resource Cards with metadata (title, author, date, type).
   - Resource types include: Video, PDF, Note, GitHub.

3. Engineering Subjects Catalog
   - Resources are strictly categorized by Engineering Classes.
   - Users can browse subjects and view only resources tied to that specific class.

4. Add Resource Flow
   - Authenticated users can contribute to the vault.
   - Captures resource title, URL, description, type, and subject.
   - Automatically associates the new resource with the user's ID.

5. Saved / Bookmarked Resources
   - Users can toggle a bookmark icon on any resource card.
   - All saved resources are securely stored in the database.
   - The 'Saved' tab displays the user's personal collection.

6. Responsive UI & Navigation
   - Desktop: Features a frosted-glass AppSidebar for global navigation.
   - Global Search input exists in the Header (UI only, logic pending).
   - High-contrast empty states for when no resources exist.

DATABASE ARCHITECTURE (Supabase)
--------------------------------------------------------------------------------
Table 1: subjects
- id (uuid)
- name (text)
- code (text)
- description (text)

Table 2: resources
- id (uuid)
- title (text)
- type (text)
- url (text)
- description (text)
- author_name (text)
- subject_id (uuid) -> Foreign Key to subjects
- user_id (uuid) -> Foreign Key to auth.users

Table 3: saved_resources
- id (uuid)
- user_id (uuid) -> Foreign Key to auth.users
- resource_id (uuid) -> Foreign Key to resources
